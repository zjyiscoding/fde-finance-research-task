# 城投调研纪要格式化整理

将城投公司调研录音的原始转写内容整理为标准化调研纪要，输出"介绍 + 区域/业务/债务三分类问答"格式，最终交付必须是 Word 成品（.docx）。

## 模板基准（强制）

- **唯一版式基准文件**：`references/reference.docx`
- **Skill 内置模板副本**：`references/reference.docx`（已与上面基准文件同步）
- **强制要求**：除正文内容（`word/document.xml` 中文本）及文档元数据时间戳外，其它版式结构必须与 `references/reference.docx` 一致，禁止自行发明或替换样式体系

---

## 内容处理核心原则

> **这是整理纪要时最重要的行为准则，优先级高于一切格式规范。**

### 原则一：转记优先，先读原文

- **先完整读取用户给的转记文件**：先看原始转记，再做整理
- **时间戳直接删除**：凡是形如 `xx:xx` 的内容都视为时间戳，只用于定位，不得出现在纪要正文里
- **以转记为第一信源**：纪要只记录领导实际说过的话，不替领导概括，不按自己的理解重写

### 原则二：尽量保留原话，只做最小整理

- **尽量使用转记原表述**：优先保留领导的措辞和语气
- **允许做最小整理**：可以去掉重复词、口语词和明显赘词，也可以在上下文明确时补齐残缺句子
- **不能改成官方腔**：纪要要像现场听出来的原始表述，不要写成二次加工后的新闻稿
- **领导没说的不写**：不无中生有，不补设定，不补背景，不补推论

### 原则三：数字与数据严格按转记

- **所有数字都以转记为准**：金额、比例、规模、期限、利率、日期等，必须严格按转记，不得修正、纠错或推算
- **数据部分不参考募集说明书**：募集说明书只用于核准专名，不用于补数字
- **数字模糊就保留模糊**：原文说“大概”“差不多”“左右”“不太清楚”，就按原样保留

### 原则四：专有名词参考募集说明书核准

以下内容可参考募集说明书核准写法：

- 人名、职位
- 机构名称、公司名称（含全称/简称）
- 项目名称、产业名称
- 财务术语、指标名称
- 政府机构名称

> 说明：募集说明书只用于核准“怎么写”，不用于补充“领导没说的内容”。若与转记冲突，除专名写法外，一律以转记为准。

### 原则五：完整性与零虚构

- **核心信息一条不漏**：转记里的核心信息必须纳入纪要
- **零虚构零假设**：不允许出现任何无依据内容，所有信息都必须能溯源到转记或专名核准

## 输入来源

用户输入可能来自以下渠道（按优先级）：

1. **用户上传的录音文件** → Alpha派自动生成ASR转写或AI纪要 → 从私域录音数据中检索
2. **用户直接粘贴的文本** → 会议要点、Q&A原文或混合纪要，视作转记内容直接处理
3. **用户指定的已有纪要** → 从私域知识库中检索特定录音纪要

## 工作流程

### Step 1：获取原始内容

**场景A：用户指定私域录音**

```
delegate_to_agent(
    agent_type="doc_searcher",
    instruction="在用户的私域录音转记数据中，检索标题包含'{录音名称}'的录音纪要，
    返回标题、时间、完整内容（full_content），取前5条。"
)
```

**场景B：用户直接提供文本**
直接使用用户提供的文本内容。

**场景C：用户上传文件**
优先完整读取上传文件内容，再进入整理流程。若文件中存在 `xx:xx` 形式内容，视为时间戳并删除，不得入稿。

### Step 2：后处理

1. **清理来源标记与时间戳**：analyst_report 输出中可能包含 `` 标记，需全部去除；凡是 `xx:xx` 形式内容一律删除（成品纪要不需要内部溯源标记和时间戳）
2. **结构完整性检查**：检查输出是否包含 `### 一、介绍`、`### 二、问答`、`### A. 区域相关`、`### B. 业务相关`、`### C. 债务相关`
3. **格式合规性检查**（逐10行扫描输出文件，发现不符合则用 `replace_file` 修正）：
  - 章节标题层级："一、介绍""二、问答"必须是 `###`（三级）
  - 分类标题层级：`A/B/C` 必须是 `###`（三级）
  - 主问题编号：Markdown 中可写 `1、` 占位，但最终 **docx 必须是 Word 自动编号**（禁止手打编号）
  - 加粗：所有问题、追问、回答必须用 `**...**` 加粗
  - 回答前缀：每个回答必须以 `**答：` 开头
  - 间距：问题与回答之间、追问与回答之间**不空行**，紧密相连
  - 指定空行：`二、问答` 上方必须空一行；`B. 业务相关` 上方必须空一行；`C. 债务相关` 上方必须空一行
4. **转为草稿 docx**（默认必须交付）：
  ```bash
   pandoc {纪要.md} -o {纪要}.draft.docx --reference-doc=references/reference.docx
   # 禁止无模板生成。必须使用 references/reference.docx 作为 reference-doc
  ```
5. **模板壳冻结 + 强校验（必须通过）**：
  ```bash
  python3 scripts/finalize_docx_from_reference.py \
    --reference references/reference.docx \
    --generated {纪要}.draft.docx \
    --output {纪要}.docx
  ```
  - 该脚本会将最终包结构强制对齐到 `references/reference.docx`，默认仅保留生成稿的 `word/document.xml`（正文）；`docProps/core.xml` 也按基准模板保持一致
  - 仅当用户明确要求保留生成时间戳/作者等元数据时，才可加 `--keep-generated-core`
  - 脚本内置结构一致性校验：`word/styles.xml`、`word/numbering.xml`、`word/settings.xml`、`word/fontTable.xml`、`word/theme/theme1.xml`、`word/webSettings.xml`、`word/_rels/document.xml.rels`、`word/footnotes.xml`、`word/endnotes.xml`、`[Content_Types].xml`
  - 若报错 `numId(s) not present in reference numbering.xml`，说明正文沿用了非基准模板编号体系，必须回到 Markdown 重新生成草稿（禁止沿用旧 docx 二次改写）
  - 若脚本报错，视为不合格，禁止交付

### Step 4：交付

将最终纪要文件通过 `answer` 工具交付给用户，附上文件路径。

## 格式规范速查


| 元素     | 格式                                                                                                           |
| ------ | ------------------------------------------------------------------------------------------------------------ |
| 标题     | `# 公司全称 日期(YYYYMMDD)`，居中，**四号字体（14pt）**，对应 Word `Title` 样式（模板样式 ID：`a9`）                           |
| 一、介绍   | `### 一、介绍`，仅「一、介绍」四字**文字底色（高亮）深蓝(RGB=0,32,96)、字体白色**，同行其余内容无底色；**小五号字体（9pt）**                                   |
| 二、问答   | `### 二、问答`，仅「二、问答」四字**文字底色（高亮）深蓝(RGB=0,32,96)、字体白色**，同行其余内容无底色；**小五号字体（9pt）**；**该行上方空一行**                     |
| 分类标题   | `### A. 区域相关` / `### B. 业务相关` / `### C. 债务相关`，仅标题文字本身（如「A. 区域相关」）**文字底色（高亮）深蓝(RGB=0,32,96)、字体白色**，同行其余内容无底色；**小五号字体（9pt）** |
| 正文字号   | **小五号字体（9pt）**，包括介绍正文、问题、追问、回答等所有非标题文字                                                                          |
| 主问题    | 深红色(RGB=192,0,0)加粗 + **Word 自动编号**（禁止手打）：`1、 **问题内容**`                                                               |
| 追问     | 深红色(RGB=192,0,0)加粗，无独立编号：`**追问内容**`                                                                             |
| 回答     | 加粗（非红色），换行但不空行：`**答：回答内容**`                                                                                     |
| 问答间距   | 问题与回答之间、追问与回答之间**换行但不空行**                                                                                       |
| 主问题块间距 | 从第2个有数字编号的问题起，每个主问题与前一个问答之间**空一行**分隔；第1个问题前不空行；介绍部分段落之间不空行                                                   |
| 指定空行   | `二、问答` 上方空一行；`B. 业务相关` 上方空一行；`C. 债务相关` 上方空一行                                                                    |
| 行间距    | 全文1.5倍行距                                                                                                        |
| 全文加粗   | 全文所有文字均加粗（包括介绍部分）                                                                                               |
| 介绍板块名称 | 业务板块名称字体标红(RGB=192,0,0)                                                                                         |
| Word导航 | 最终 docx 中标题、章节、分类必须使用 Word 标题样式，确保出现在 Word 导航窗格中                                                             |


## 分类标准

问答按核心主题分为三类，详细分类规则参见 `references/classification-rules.md`。

**快速判断：**

- **区域**：区域经济、平台整合、评级规划、区域政策
- **业务**：业务运营、项目投资、土地开发、市场化转型、财政补贴
- **债务**：债务规模结构、融资成本、隐债化债、债券发行、银行授信、非标融资、担保拆借、名单管理

## 关键规则

1. **完整性第一**：录音中每个问答必须保留，不得遗漏
2. **主问题 vs 追问**：新话题 = 主问题（加编号）；同话题延伸 = 追问（不加编号）
3. **去重合并**：会议要点与Q&A重复时，保留更完整版本，但不丢失任何信息点
4. **数据准确**：所有数字、比例、时间必须与原文完全一致
5. **保留不确定性**：原文中的"约""大概""不太清楚"等表述必须保留

## Word 文件格式强约束（以蚌埠模板为唯一标准）

### 基准文件与允许差异

- 基准文件：`references/reference.docx`
- Skill 模板副本：`references/reference.docx`
- 允许差异仅限：正文文字内容（公司名、日期、问答内容）与 `docProps/core.xml` 的时间戳类元数据
- 不允许差异：样式、编号、主题、字体表、页面/段落默认设置、文档关系文件

### 必须与模板一致的结构文件

- `word/styles.xml`
- `word/numbering.xml`
- `word/settings.xml`
- `word/fontTable.xml`
- `word/theme/theme1.xml`
- `word/webSettings.xml`
- `word/_rels/document.xml.rels`
- `word/footnotes.xml`
- `word/endnotes.xml`

### 该模板的关键样式映射（用于排错）

| 内容类型 | 样式 ID | 说明 |
|---------|---------|------|
| 标题（公司名+日期） | `a9` | 样式名 `Title`，居中、14pt、楷体 |
| 章节/分类标题 | `3` | 样式名 `heading 3`，深蓝底白字 |
| 主问题（A类默认） | `4` | 样式名 `4_正文 & 问题`，红色加粗，自动编号 |
| 主问题（B/C类） | `a3` + 段落 `numPr` | 自动编号，禁止手打 `1、` |
| 正文/回答 | `5` | 样式名 `5_正文 & 回答`，黑色加粗 |

### 指定空行规则（新增强制）

- `二、问答` 上方必须空一行
- `B. 业务相关` 上方必须空一行
- `C. 债务相关` 上方必须空一行
- 问题与回答、追问与回答之间不空行

### 生成与校验顺序（必须执行）

1. 先按内容规则生成 Markdown（标题与各级标题使用 `###` 结构）
2. 使用 `pandoc ... --reference-doc=references/reference.docx` 转成草稿 docx（`{纪要}.draft.docx`）
3. 运行 `python3 scripts/finalize_docx_from_reference.py --reference references/reference.docx --generated {纪要}.draft.docx --output {纪要}.docx` 冻结模板壳
4. 仅当脚本通过时交付；脚本失败则回到内容生成环节重做，禁止手工改动结构文件
