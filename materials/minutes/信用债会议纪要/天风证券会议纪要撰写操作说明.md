#### 撰写要求

1. **问题编号**：每个分类内独立编号，使用阿拉伯数字（1. 2. 3. ...）。
2. **问题提炼**：
   - 将提问者的口语化问题提炼为简洁、清晰的问句。
   - 保留问题的具体指向，不要过度泛化。
   - 示例：录音原文"就是说你们那个城市运营那一块是不是基本上就靠卖地的" → 整理为"城市运营板块是不是基本上是以土地出让来覆盖支出的？"
3. **回答处理**：
   - 以"答："开头。
   - 保留被访谈方的第一人称。
   - 保留关键数据、时间节点、政策背景。
   - 删除重复表述和无信息量的语气过渡。
   - 当回答涉及多个要点时，可使用分号或句号分隔，但**不使用项目符号**（除非原始回答本身有明确的列举结构）。
4. **追问处理**：
   - 同一话题的连续追问**不另起编号**，直接跟在上一个回答之后。
   - 追问同样需要提炼为简洁问句。
   - 每一轮追问的回答同样以"答："开头。
5. **问答归并**：如果录音中同一话题在不同时间段被多次提及，应将相关问答**合并到同一编号下**，保持信息的集中性。

### 4.5 排版与格式细节

| 项目 | 规范 |
|---|---|
| 字体 | 如输出为 docx，正文宋体/仿宋，标题黑体（根据用户要求调整） |
| 标点 | 使用中文标点（全角），数字与英文使用半角 |
| 数字 | 具体数值用阿拉伯数字（如"350亿"），概数用汉字（如"几个"） |
| 百分比 | 统一使用"%"（如"65-67%"） |
| 公司/机构名称 | 首次出现用全称，后续可用简称，简称需在首次出现时标注 |
| 段落 | 每个层级之间空一行，同层级内容紧凑排列 |

## 五、特殊情况处理

### 5.1 录音中出现敏感信息
如涉及具体人名、未公开的政策信息等，Claude 应予以保留但标注 `【敏感信息，请确认是否保留】`。

### 5.2 录音质量差导致大段缺失
标注 `【此处录音不清晰，约X分钟内容缺失】`，并根据上下文推测话题，写明 `【推测话题为：XXX】`。

### 5.3 多人同时发言或打断
尽量根据语境还原完整的问答逻辑。如果无法判断归属，标注 `【发言人待确认】`。

### 5.4 信息与公开资料矛盾
如被访谈方提供的数据与公开可查的数据（如评级报告、财报）明显不一致，Claude 应标注 `【与公开信息可能存在差异，建议核实】`。

## 六、输出检查清单

Claude 在完成会议纪要后，应自查以下项目：

- [ ] 文档结构是否严格遵循"一、介绍 → 二、问答（A/B/C）"三大类
- [ ] "介绍"部分是否涵盖了公司核心财务指标（总资产、净资产、负债率）
- [ ] "介绍"部分的业务板块是否完整、层次清晰
- [ ] 所有问答是否已正确归类到 A/B/C
- [ ] 同一话题的追问是否合并在同一编号下
- [ ] 关键数据是否前后一致
- [ ] 错别字和术语是否已修正
- [ ] 模糊/不确定内容是否已标注
- [ ] 语气词和冗余表述是否已清理
- [ ] 公司名称首次出现是否为全称
